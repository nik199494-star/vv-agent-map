# Испытательный контур

Preview запускается от push только в ветку codex/demand-pipeline. Workflow читает содержимое репозитория с правом contents: read. В нём отсутствуют шаги публикации и права Pages. Режим fixture собирает архив на базе уже опубликованного исторического снимка. Режим sheets сверяет закрытую копию с паспортом и показывает только итог проверки, без архива данных.

Для workflow_dispatch GitHub требует наличие workflow в ветке по умолчанию. Запуск preview от push позволяет сохранить main и настройки Pages в текущем состоянии. [Документация GitHub](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

## Копии и Apps Script

1. Используйте закрытые копии рабочей книги, Базы знаний и отдельной агентской витрины. Копируйте книгу с формулами и скрытыми вкладками. В рабочей копии откройте «Расширения → Apps Script», сохраните прежний Код.gs и проверьте конфигурацию проекта.
2. Сгенерируйте единый файл из закрытой рабочей выгрузки. Генератор останавливается при расхождении точек подключения и проверяет синтаксис. Вставьте файл .data/preview-install/Code.preview.gs в рабочую копию Apps Script. Если манифест явно задаёт scopes, для этого файла нужен доступ к Google Sheets из нескольких книг. Код запускает только локальную обработку в Google Sheets.

       node scripts/build-preview-apps-script.mjs путь-к-Код.gs

3. Откройте «Настройки проекта → Свойства скрипта». Укажите VV_PREVIEW_WORK_ID с ID копии рабочей книги, VV_PREVIEW_KB_ID с ID копии Базы знаний и VV_PREVIEW_AGENT_ID с ID копии отдельной агентской витрины. В VV_PREVIEW_ORIGINAL_WORK_ID укажите ID исходной рабочей книги, чтобы скрипт мог найти старые ссылки и проверить защиту от установки на оригинале. ID — часть ссылки Google Sheets между /d/ и /edit. Изменения из пакета разрешены только для зарегистрированной рабочей копии. Сохраните настройки и перезагрузите таблицу.
4. Выберите «ВВ Preview → Связать испытательные копии». Разрешите IMPORTRANGE между тестовыми книгами там, где Google показывает «Разрешить доступ». Проверьте четыре формулы A3 и A5 на каждой паре листов «Потребность города» и «Потребность точки». Ссылки должны идти от копии агента к копии Базы знаний, от неё к копии рабочей книги.
5. Вызовите «Проверить ссылки и формулы v2». Проверьте наличие формул и ошибки расчёта в первых 30 строках листов _NORM v2, _FULL v2 live, _POINTS v2 calc, _CITIES v2 calc и _Telegram calc. Отдельно сверьте нестандартные импортируемые диапазоны, именованные функции и внешние связи, которые строятся динамически.
6. Вставьте свежую FULL в рабочую копию и выполните «Принять снимок и создать паспорт preview». Сверьте дату, города, ТТ и недобор в двух копиях витрин. В агентской копии появится «Паспорт preview» с маркером в A2.

## Секреты для владельца

1. В Google Cloud Console выберите проект для испытательного контура. Через «APIs & Services → Library» включите Google Sheets API. [Включение API](https://cloud.google.com/endpoints/docs/openapi/enable-api)
2. В «IAM & Admin → Service Accounts» создайте отдельную сервисную учётную запись. На вкладке «Keys» выберите «Add key → Create new key → JSON». Роли проекта для чтения таблицы ей не нужны. Если организация запрещает выгрузку ключей, согласуйте использование другой схемы авторизации с администратором. [Ключи сервисных аккаунтов](https://cloud.google.com/iam/docs/keys-create-delete)
3. В Google Sheets поделитесь **только испытательной агентской витриной** с client_email из ключа и выдайте роль «Читатель». В рабочую книгу, Базу знаний и production права этому читателю не выдавайте.
4. В GitHub откройте «Settings → Environments → New environment». Создайте demand-preview. В «Deployment branches and tags» выберите «Selected branches and tags» и добавьте правило Branch с точным именем codex/demand-pipeline. При наличии второго ответственного задайте его как проверяющего. [Окружения GitHub Actions](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments)
5. В «Environment secrets» добавьте VV_PREVIEW_AGENT_ID со значением ID испытательной агентской витрины и VV_PREVIEW_SHEETS_READER со всем содержимым скачанного JSON. Не добавляйте их в общие секреты репозитория или файлы ветки. Для Apps Script испытательного контура GitHub PAT не нужен.

## Сквозная проверка

1. После появления паспорта измените файл .github/preview-request.json исключительно в ветке codex/demand-pipeline. Укажите режим sheets и маркер из A2.

       {"mode":"sheets","requestId":"UUID из A2"}

2. Откройте новый запуск «Изолированный preview потребности». Если настроено подтверждение окружения, одобрите эту задачу. Задача sheets должна проверить точный маркер, подпись витрины, города, количества, недобор и координаты. Она доступна только с push в указанную ветку.
3. Для отказного теста замените маркер на другой UUID. Задача должна завершиться ошибкой до сборки. Верните режим fixture в этом же файле после проверки, чтобы следующие push не запускали чтение закрытой книги.
4. Сверьте, что origin/main и публичный снимок сохранили прежние версии. Готовность к выпуску рассматривается только после проверки живых скрытых листов v2, связи копий и успешного прогона sheets. Запуск боевой публикации рассматривается отдельно.
