# Откат карты с прогретым кешем

Этот PR использует инфраструктуру PR №1. Модуль браузера и резервное копирование поставляются отдельным изменением. Перед первым обновлением данных операторы открытых вкладок должны один раз перезагрузить карту, чтобы загрузить код с поддержкой отката. Данные для последующего выпуска должны содержать уникальный `snapshotId`.

## Сохранить выпуск перед обновлением

1. Сверить текущий GitHub Pages deployment и убедиться, что публичная карта загружает модуль `rollback.js`.
2. Выполнить `node scripts/pages-baseline.mjs capture .data/pages-before-release`. У каждого HTTP 503 до трёх попыток с ограниченной паузой. Устойчивая ошибка заканчивает команду до создания готового архива.
3. Проверить архив по публичной карте командой `node scripts/pages-baseline.mjs verify .data/pages-before-release/baseline-manifest.json`. Проверка охватывает все перечисленные статические файлы, контрольную квитанцию и квитанцию отката, включая отсутствие допустимых необязательных файлов. Ошибка любого хеша останавливает процедуру.
4. Согласовать выпуск данных отдельно и сохранить байты публикуемого `demand.json`, чтобы при сбое опознать отменяемый выпуск.

## Подготовить восстановление

1. Перед восстановлением выполнить `node scripts/pages-baseline.mjs restore .data/pages-before-release .data/failed-demand.json .data/pages-restore`. Команда проверяет архив, идентификатор и время отменяемого выпуска. В новую папку попадают прежние файлы с исходными байтами и новая квитанция `rollback.json`.
2. После отдельного разрешения восстановить файлы через действующий способ размещения. Сохранить URL и источник Pages. Локальный `baseline-manifest.json` используется для проверки.
3. Выполнить `node scripts/pages-baseline.mjs verify .data/pages-restore/baseline-manifest.json`. На странице с загруженным отменённым снимком нажать «Обновить», сверить дату, недобор и маркеры. Проверить чистую вкладку отдельно.
4. Квитанция привязывает восстановленные данные и оба файла географии к идентификатору и времени отменяемого выпуска. Браузер проверяет три SHA-256 и хранит отметку отката рядом со снимком в IndexedDB. Задержавшийся ответ CDN с отменённой версией отклоняется. Следующая версия должна иметь новое время публикации.

## Испытательный стенд

Команда `node scripts/rollback-stand.mjs` слушает только `127.0.0.1` и печатает путь к файлу `phase.txt`. Стенд использует условные показатели и архивирует начальное состояние. Вставляйте последовательно одно слово в указанный файл и проверяйте страницу.

| Этап | Действие в браузере | Ожидаемый результат |
| --- | --- | --- |
| `failed` | Открыть карту | Недобор 20, 0 из 1 маркеров |
| `mixed` | Нажать «Обновить» | Архивные данные с несовпадающими координатами не проходят проверку, остаётся 20 и 0 из 1 |
| `restored` | Нажать «Обновить» в той же вкладке | Недобор 10 и 1 из 1 маркеров |
| `stale` | Нажать «Обновить» | Ответ с отменённым выпуском отклонён, остаётся 10 |
| `offline` | Перезагрузить вкладку | При 503 показан восстановленный кеш с недобором 10 и маркером |
| `forward` | Нажать «Обновить» | Новая версия загружается с недобором 30 |

При проверке хешей стенд отклонил частичную выкладку и подтвердил 23 позиции манифеста после восстановления. В начальном резервном копировании стенд получил два ответа HTTP 503 и успешно повторил запрос. Устойчивый ответ HTTP 503 проверен в автоматическом тесте.
